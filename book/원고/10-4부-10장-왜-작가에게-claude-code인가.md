# 10장. 왜 작가에게 Claude Code인가

여기까지 오신 여러분은 이미 한 권 분량의 원고를 손에 쥐고 있을 것입니다. 챗봇과 대화하며 목차를 세우고, 초고를 쓰고, 퇴고까지 마쳤으니까요. 그런데 원고가 열 개 장을 넘어가는 순간부터, 어딘가 삐걱거리는 느낌을 받지 않으셨나요? 대화창에 원고를 붙여넣는 일이 점점 버거워지고, 어제 고친 내용을 오늘 다시 설명해야 하고, 같은 수정 지시를 챕터마다 반복하게 됩니다.

저는 이 지점을 "채팅의 한계선"이라고 부릅니다. 책 한 권은 채팅창 하나에 담기에는 너무 큰 프로젝트입니다. 파일은 여러 개고, 작업은 반복되고, 버전은 계속 쌓입니다. 문제는 AI가 부족해서가 아니라, AI를 만나는 방식이 채팅창에 갇혀 있어서 생깁니다.

4부에서는 그 한계선을 넘는 도구, 클로드 코드(Claude Code)를 소개합니다. 이름에 '코드'가 들어가서 개발자 전용처럼 들리지만, 안심하세요. 이 장을 읽고 나면 여러분은 "내 컴퓨터의 원고 폴더에서 직접 일하는 AI 편집 조수"를 한 명 들이게 됩니다. 터미널의 검은 화면을 몰라도 됩니다. 이 장이 약속하는 것은 하나입니다. 채팅창 밖으로 나와, 원고 폴더 앞에 AI를 앉히는 것.

## 채팅형 AI의 한계: 긴 원고, 흩어진 파일, 반복 작업

먼저 우리가 무엇 때문에 답답했는지를 정확히 짚고 넘어가겠습니다. 문제를 알아야 도구의 가치가 보입니다.

**첫째, 긴 원고입니다.** 채팅형 AI와 일하려면 원고를 대화창에 붙여넣어야 합니다. 한두 챕터까지는 괜찮습니다. 하지만 전체 원고를 놓고 "3장과 7장의 설명이 겹치는지 봐줘" 같은 요청을 하려면, 매번 수만 자를 복사해 넣어야 합니다. 대화가 길어지면 AI가 앞부분 맥락을 놓치는 일도 생깁니다. 2부에서 배운 프로젝트 기능이 이 문제를 어느 정도 덜어 주지만, 파일을 업로드하고 수정 결과를 다시 내려받아 원본에 반영하는 일은 여전히 사람의 몫입니다. 참고로 ChatGPT는 Plus 요금제 기준 프로젝트당 파일 25개 제한이 있어, 장편 원고와 자료를 모두 담기에는 빠듯합니다.

**둘째, 흩어진 파일입니다.** 책 한 권의 재료는 원고만이 아닙니다. 기획서, 목차, 챕터별 원고, 취재 메모, 인용 출처 목록, 표지 시안 문구까지. 실제 집필은 수십 개의 파일을 오가며 진행됩니다. 채팅형 AI는 이 파일들을 스스로 열어 볼 수 없습니다. 여러분이 일일이 꺼내서 보여 줘야 하고, AI는 보여 준 것만 압니다. "목차 파일과 실제 원고 제목이 어긋난 곳을 찾아줘" 같은, 파일 사이를 넘나드는 요청은 구조적으로 어렵습니다.

**셋째, 반복 작업입니다.** 퇴고 중에 용어 하나를 바꾸기로 결정했다고 해 봅시다. 원고 전체에서 'e북'을 '전자책'으로 통일하려면, 채팅 방식으로는 챕터를 하나씩 붙여넣고, 수정본을 받고, 원본에 옮겨 붙이는 일을 열두 번 반복해야 합니다. 한 번의 결정이 열두 번의 노동이 되는 구조입니다. 이런 작업이 출간 전까지 몇 번이나 반복되는지, 겪어 본 분은 아실 겁니다.

세 문제의 뿌리는 하나입니다. **채팅형 AI는 결과물을 '말'로 돌려주고, 그 말을 파일에 옮기는 일은 언제나 사람이 한다**는 것. 전화기 너머의 상담원에게 서류를 한 장씩 읽어 주며 일하는 셈입니다. 상담원이 아무리 유능해도, 서류 정리는 결국 내 손으로 해야 합니다.

오해는 없으시길 바랍니다. 채팅형 AI가 나쁘다는 이야기가 아닙니다. 아이디어 발산, 리서치, 짧은 글 다듬기에는 지금도 채팅이 가장 빠릅니다. 문제는 원고가 '프로젝트'의 규모가 되었을 때입니다. 서류가 서너 장일 때는 전화 상담으로 충분하지만, 서류가 수십 장이 되면 사무실로 출근하는 조수가 필요합니다. 이 책의 권장 분업도 그렇습니다. **생각을 넓히는 일은 채팅에게, 원고 파일을 다루는 일은 이제부터 소개할 도구에게.**

## Claude Code란: 파일을 직접 읽고 쓰고 실행하는 AI 에이전트

클로드 코드는 앤트로픽(Anthropic)이 만든 AI 에이전트입니다. '에이전트'라는 말이 어렵게 들린다면 이렇게 이해하시면 됩니다. **대답만 하는 AI가 아니라, 일을 맡기면 스스로 움직여 끝내는 AI.** 여러분이 지정한 폴더 안에서 파일을 직접 열어 읽고, 고쳐 쓰고, 필요한 작업을 실행한 뒤 결과를 보고합니다.

예를 들어 "원고 폴더에서 'e북'을 모두 '전자책'으로 바꿔줘"라고 말하면, 클로드 코드는 폴더 안의 파일들을 훑어 해당 표현이 나오는 곳을 찾고, 하나하나 수정한 뒤, "12개 파일에서 37곳을 바꿨습니다"라고 알려 줍니다. 여러분이 복사해 붙여넣을 것은 없습니다. 전화 상담원이 아니라, 내 서재에 들어와 앉은 편집 조수인 셈입니다.

"그래도 개발자 도구 아닌가요?"라는 질문을 많이 받습니다. 출발은 분명 프로그래머를 위한 도구였습니다. 그런데 흥미로운 변화가 보고되고 있습니다. 코딩이 아닌 업무 용도의 사용이 개발 용도를 추월했다는 통계가 나올 만큼, 비개발자의 활용이 빠르게 늘고 있습니다. 이유는 단순합니다. 프로그램 코드도 텍스트 파일이고, 우리의 원고도 텍스트 파일이기 때문입니다. "여러 텍스트 파일을 읽고, 규칙에 맞게 고치고, 결과를 정리한다"는 능력은 코드에든 원고에든 똑같이 통합니다. 오픈소스 커뮤니티에는 클로드 코드로 장편 소설을 쓰는 프로젝트가 공개되어 있을 정도입니다.

작가의 하루에 대입해 보면 그림이 선명해집니다. 아침에 폴더를 열고 "어제 쓴 5장 이어서 쓸 건데, 앞 장들과 겹치는 내용이 있는지 먼저 확인해줘"라고 말합니다. 점심에는 "오전에 쓴 부분에서 문장이 늘어지는 곳을 표시해줘"라고 부탁합니다. 저녁에는 "오늘 작업 정리해서 저장해줘"로 하루를 닫습니다. 이 모든 과정에서 여러분이 복사하고 붙여넣는 일은 없습니다. 원고는 처음부터 끝까지 폴더 안의 파일로 존재하고, AI가 그 파일들 사이를 오가며 일합니다.

물론 "AI가 내 파일을 마음대로 고친다니 무섭다"는 걱정이 들 수 있습니다. 당연한 걱정이고, 안전장치가 있습니다. 클로드 코드는 파일을 수정하거나 무언가를 실행하기 전에 **여러분에게 허락을 구합니다.** 무엇을 어떻게 바꾸려는지 보여 주고, 여러분이 승인해야 진행합니다. 여기에 다음 장에서 배울 버전 관리를 더하면, 어떤 수정이든 이전 상태로 되돌릴 수 있습니다. "허락받고 일하고, 언제든 되돌릴 수 있는 조수"라고 생각하시면 됩니다.

작가에게 클로드 코드가 열어 주는 가능성은 크게 네 가지입니다. 이 네 가지가 4부 전체의 지도입니다.

1. **긴 원고 집필** — 챕터별 파일로 나뉜 원고를 통째로 읽고 쓰며 함께 작업합니다. (11장)
2. **버전 관리** — "어제 버전으로 되돌려줘"를 자연어로 처리합니다. (11장)
3. **전권 일괄 수정** — 용어 통일, 표기 교정을 한 문장으로 끝냅니다. (11장)
4. **반복 작업 자동화** — 나만의 교정 체크리스트를 패키징하고, 정기 작업을 예약합니다. (12장)

## 작가를 위한 설치와 시작: 데스크톱 앱이면 충분합니다

이제 시작해 봅시다. 가장 먼저 말씀드리고 싶은 것은 이것입니다. **터미널을 몰라도 됩니다.** 클로드 코드는 터미널 명령창에서도 쓸 수 있지만, 데스크톱 앱과 웹·모바일에서도 쓸 수 있게 확장되었습니다. 이 책에서는 비개발자에게 가장 문턱이 낮은 **데스크톱 앱**을 기준으로 안내합니다. 검은 화면에 명령어를 입력하는 일은 이 책에 나오지 않습니다. 여러분이 할 일은 지금까지 해 온 것과 같습니다. 한국어로 말을 거는 것.

비용 이야기도 먼저 정리하겠습니다. 클로드 코드는 별도 구독 상품이 아닙니다. **Claude Pro 구독(월 $20, 연 결제 시 월 $17 수준)에 포함**되어 있습니다(2026년 7월 기준, 최신 정보는 공식 페이지 확인). 2부에서 Claude Pro를 이미 쓰고 계신 분이라면 추가 비용 없이 오늘 바로 시작할 수 있다는 뜻입니다. 참고로 같은 구독에는 비개발자용 에이전트 워크스페이스인 코워크(Cowork)도 포함되어 있는데, 이 책에서는 원고 파일 작업에 초점을 맞춰 클로드 코드를 중심으로 설명합니다.

시작 절차는 세 단계입니다. 버튼의 위치나 메뉴 이름은 업데이트에 따라 달라질 수 있으니, 화면보다 **원리**를 기억해 주세요.

**1단계: Claude 데스크톱 앱을 설치하고 로그인합니다.** 앤트로픽 공식 사이트에서 데스크톱 앱을 내려받아 설치하고, Pro 계정으로 로그인합니다. 이미 앱을 쓰고 계시다면 최신 버전으로 업데이트만 확인하세요.

[그림: Claude 데스크톱 앱 첫 화면 — 일반 채팅과 구분되는 에이전트(코드) 작업 진입점 표시]

**2단계: 작업 폴더를 지정합니다.** 클로드 코드와의 대화는 언제나 "어느 폴더에서 일할 것인가"에서 시작합니다. 이것이 채팅과 가장 다른 점입니다. 채팅은 빈 방에서 시작하지만, 클로드 코드는 여러분의 서재, 즉 원고 폴더에서 시작합니다. 지정한 폴더 바깥은 함부로 건드리지 않으므로, 원고용 폴더를 하나 만들어 지정하면 안전한 울타리가 됩니다.

[그림: 작업 폴더 선택 화면 — 원고 폴더를 지정하는 모습]

**3단계: 첫 대화를 나눕니다.** 폴더를 지정했다면 이렇게 말을 걸어 보세요. "이 폴더에 어떤 파일이 있는지 알려줘." 클로드 코드가 폴더 내용을 읽고 정리해서 답합니다. 파일을 고치는 작업을 시키면 승인 요청이 뜨는데, 처음에는 내용을 하나하나 읽어 보고 승인하는 습관을 들이시길 권합니다. 조수와 신뢰를 쌓는 과정이라고 생각하세요.

[그림: 첫 대화 화면 — 파일 목록 요청과 응답, 수정 승인 요청 표시 예시]

한 가지 마음가짐도 챙겨 두시면 좋겠습니다. 처음 며칠은 클로드 코드가 낯설게 느껴질 수 있습니다. 채팅과 달리 "어느 파일에서, 무엇을, 어떻게"를 조금 더 구체적으로 말해 줘야 결과가 좋아지기 때문입니다. 하지만 이것은 단점이 아니라 훈련입니다. 2부에서 프롬프트를 다듬으며 익힌 "구체적으로 요청하기" 근육이 여기서 그대로 쓰입니다. 그리고 채팅과 마찬가지로, 결과가 마음에 들지 않으면 "아니, 이렇게 말고 이렇게"라고 다시 말하면 됩니다. 대화는 계속 이어집니다.

첫날부터 대단한 것을 시킬 필요는 없습니다. 저는 수강생들에게 첫 실습으로 늘 같은 것을 권합니다. 지금까지 쓴 원고 파일 몇 개를 폴더에 넣고, "이 원고들을 읽고 각 파일이 무슨 내용인지 한 줄씩 요약해줘"라고 말해 보는 것. 내 원고를 AI가 파일째 읽고 정리해 주는 첫 경험이, 채팅과는 다른 세계가 열렸다는 감각을 만들어 줍니다.

[저자 사례: 터미널이라는 말만 들어도 손사래 치던 수강생이 데스크톱 앱으로 시작해, 첫 주에 전권 용어 통일까지 해낸 이야기 — "이럴 줄 알았으면 진작 쓸걸"이라는 반응 포함]

## 프롬프트 박스: 첫날 클로드 코드에게 건네는 말

아래 문장들을 그대로 복사해 써 보세요. 명령어가 아니라 전부 평범한 한국어라는 점에 주목하시기 바랍니다.

```
이 폴더에 어떤 파일이 있는지 알려주고, 각 파일이 무슨 내용인지 한 줄씩 요약해줘.
```

```
[파일명].md 파일을 읽고, 이 글의 장점 2가지와 아쉬운 점 2가지를 알려줘.
아직 파일은 고치지 말고 의견만 줘.
```

```
[파일명].md에서 맞춤법이 틀린 곳을 찾아서 고쳐줘.
고치기 전에 어디를 어떻게 바꿀 건지 먼저 보여줘.
```

```
방금 네가 바꾼 내용을 표로 정리해줘. 왼쪽에는 원래 문장, 오른쪽에는 바뀐 문장.
```

두 번째와 세 번째 프롬프트처럼 "아직 고치지 말고", "먼저 보여줘"라는 말을 덧붙이는 습관을 추천합니다. 검토 후 실행이라는 안전한 작업 리듬이 여기서부터 만들어집니다.
