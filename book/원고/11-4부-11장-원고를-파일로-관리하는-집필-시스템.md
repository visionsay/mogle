# 11장. 원고를 파일로 관리하는 집필 시스템

혹시 지금 여러분의 원고는 어디에 있나요? 많은 분이 이렇게 답합니다. "구글 문서 하나에 전부요." 그 문서의 이름은 아마 `최종원고_진짜최종_수정2`쯤 될 겁니다. 한 문서에 10만 자가 넘게 쌓이면 스크롤만으로 지치고, 지난주에 고친 문장이 어디였는지 찾는 데 10분이 걸립니다. 잘못 지운 문단을 복구하려고 버전 기록을 뒤지다 포기한 경험도 있으실 겁니다.

3장에서 원고 버전 관리의 기초를 구글 문서로 시작했다면, 이 장에서는 한 단계 올라섭니다. 원고를 챕터별 파일로 나누고, 전문 작가와 개발자들이 쓰는 버전 관리 도구를 자연어로 부리고, 내 책의 규칙을 AI에게 상시 학습시키는 것. 이 장이 약속하는 것은 **잃어버리지 않고, 헤매지 않고, 반복하지 않는 집필 시스템**입니다.

## 원고 폴더 설계: 왜 챕터별 마크다운 파일인가

먼저 원고를 담는 그릇부터 바꿉니다. 결론부터 말하면, **챕터 하나 = 마크다운 파일 하나**입니다.

마크다운(Markdown)은 어렵지 않습니다. 그냥 텍스트 파일인데, 몇 가지 약속이 있을 뿐입니다. `#`을 붙이면 제목, `##`은 소제목, `**단어**`는 강조. 이게 거의 전부입니다. 확장자는 `.md`이고, 메모장으로도 열립니다. 워드처럼 글자 크기나 폰트를 고민할 필요가 없어서 오히려 글에만 집중하게 됩니다.

왜 이 방식이 좋을까요? 네 가지 이유가 있습니다. 첫째, **AI가 다루기 가장 좋은 형식**입니다. 클로드 코드는 텍스트 파일을 통째로 읽고 쓰는 데 능숙합니다. 둘째, **어디서나 열립니다.** 특정 프로그램에 갇히지 않으니 10년 뒤에도 열 수 있습니다. 셋째, 잠시 후 배울 **버전 관리와 궁합이 완벽**합니다. 넷째, 나중에 **워드·EPUB 등으로 변환하기 쉽습니다.** 3부에서 만든 최종 파일도 결국 이 원본에서 출발하게 됩니다.

폴더 구조는 다음을 추천합니다. 제가 실제로 쓰는 뼈대입니다.

```
내-전자책/
├── CLAUDE.md              ← 내 책의 규칙 파일 (이 장 마지막 절에서 작성)
├── 기획/
│   ├── 기획서.md
│   ├── 목차.md
│   └── 독자-페르소나.md
├── 원고/
│   ├── 00-프롤로그.md
│   ├── 01-1장-내-경험을-책의-재료로.md
│   ├── 02-2장-주제와-목차-설계.md
│   └── ...
├── 자료/
│   ├── 인용-출처.md
│   └── 취재-메모.md
└── 산출물/                ← 12장에서 만들 보도자료·SNS 콘텐츠가 쌓이는 곳
```

파일명 규칙이 하나 있습니다. **앞에 두 자리 숫자를 붙이세요.** `01-`, `02-`처럼요. 파일이 언제나 책의 순서대로 정렬되고, AI에게 "3장 다음에 새 장을 끼워줘" 같은 지시를 하기도 쉬워집니다.

이 구조를 손으로 만들 필요는 없습니다. 첫 일감으로 클로드 코드에게 맡기세요.

```
내 전자책 프로젝트 폴더를 만들어줘.
- 기획, 원고, 자료, 산출물 폴더를 만들고
- 원고 폴더에는 목차에 맞춰 챕터별 빈 마크다운 파일을 만들어줘.
  파일명은 "01-1장-제목" 형식으로.
- 각 파일 첫 줄에는 "# n장. 제목"을 넣어줘.
목차는 기획/목차.md 파일에 있어.
```

기존 원고의 이사도 간단합니다. 구글 문서에서 전체 원고를 텍스트로 내려받아 폴더에 넣고 이렇게 말하면 됩니다. "이 파일을 목차 기준으로 챕터별 파일로 나눠서 원고 폴더에 저장해줘."

"그럼 글은 어디서 쓰나요?"라는 질문이 나올 차례입니다. 마크다운 파일은 메모장부터 전문 마크다운 편집기까지 어디서든 열어 쓸 수 있고, 클로드 코드와의 대화 안에서 받아쓰게 할 수도 있습니다. 저는 이렇게 권합니다. 문장을 직접 쓰는 몰입의 시간에는 여러분이 익숙한 편집기에서 쓰고, 구조를 바꾸거나 여러 파일을 손보는 작업은 클로드 코드에게 맡기는 것. 그릇이 표준 텍스트 파일이기 때문에 어떤 조합이든 자유롭습니다.

## git 버전 관리를 자연어로: "어제 버전으로 되돌려줘"

이제 이 시스템의 심장인 버전 관리입니다. 깃(git)은 전 세계 개발자들이 쓰는 버전 관리 도구입니다. 원리는 단순합니다. **원하는 순간마다 폴더 전체의 스냅샷을 찍어 두고, 언제든 그 시점으로 돌아갈 수 있게 해 주는 장부**입니다. 게임의 세이브 포인트와 같습니다. 보스전(대규모 퇴고) 전에 저장해 두면, 결과가 마음에 안 들 때 다시 시작할 수 있습니다.

문제는 git이 원래 명령어로 조작하는 도구라는 점입니다. 그래서 작가들이 접근하기 어려웠습니다. 하지만 여러분은 명령어를 한 줄도 배울 필요가 없습니다. **클로드 코드가 여러분의 한국어를 git 명령으로 통역해 실행**해 주기 때문입니다. 우리는 원리만 알면 됩니다. "저장한다, 비교한다, 되돌린다." 이 세 동사가 전부입니다.

**저장하기.** 하루 집필을 마칠 때마다 이렇게 말하세요.

```
오늘 작업한 내용을 버전으로 저장해줘.
어떤 파일이 얼마나 바뀌었는지 요약해서 저장 메모에 남겨줘.
```

처음 한 번은 "이 폴더에 버전 관리를 시작해줘"라고 하면 클로드 코드가 초기 설정까지 알아서 해 줍니다. 이후로는 저장 요청만 반복하면 됩니다. 저장 메모(커밋 메시지라고 부릅니다)도 AI가 대신 써 주니, 여러분은 "저장해줘" 한마디면 충분합니다.

**비교하기.** 퇴고 중에는 이런 요청이 빛을 발합니다.

```
4장 파일이 어제 저장본과 비교해서 뭐가 달라졌는지 보여줘.
바뀐 문장을 전후 비교로 정리해줘.
```

**되돌리기.** 그리고 이 장의 제목이기도 한 마법의 문장입니다.

```
4장을 어제 저녁에 저장한 버전으로 되돌려줘.
되돌리기 전에, 지금 상태도 따로 저장해 두고 진행해줘.
```

두 번째 줄이 중요합니다. 되돌리기 전에 현재 상태를 저장해 두면, "되돌린 것을 다시 되돌리는" 일도 가능합니다. 어느 쪽으로도 잃는 것이 없어집니다. 이 안전망이 생기면 글쓰기가 달라집니다. 과감하게 문단을 들어내고, 실험적으로 고쳐 볼 용기가 생깁니다. 언제든 돌아갈 수 있으니까요.

습관은 하나만 만드시면 됩니다. **하루의 집필을 끝낼 때 = 저장을 요청할 때.** 이를 닦듯 반복하세요. 12장에서는 이 저장마저 자동화하는 법을 다룹니다.

덤으로 얻는 것이 하나 더 있습니다. 매일의 저장 기록이 쌓이면 그 자체가 집필 일지가 됩니다. "지난 2주 동안의 저장 기록을 날짜별로 정리해줘"라고 요청하면, 언제 어떤 장을 썼고 어디서 오래 멈췄는지가 한눈에 보입니다. 30일 로드맵의 중간 점검에 이만한 자료가 없습니다. 슬럼프가 온 주간을 숫자로 확인하고 나면, 막연한 자책 대신 구체적인 계획 수정이 가능해집니다.

## 전권 일괄 작업: 용어 통일·표기 교정·호칭 변경을 한 문장으로

챕터별 파일과 버전 관리가 갖춰지면, 채팅형 AI로는 불가능했던 작업이 열립니다. 원고 전체를 한 번에 손보는 일괄 작업입니다.

**용어 통일.** 긴 집필 기간 동안 같은 대상을 다르게 부르는 일은 누구에게나 일어납니다. 이렇게 요청하세요.

```
원고 폴더 전체에서 '전자책'과 'e북', '이북'이 섞여 쓰이고 있어.
전부 '전자책'으로 통일해줘.
단, 고유명사나 인용문 안에 있는 것은 바꾸지 말고 따로 알려줘.
끝나면 파일별로 몇 곳을 바꿨는지 표로 보고해줘.
```

"인용문 안은 바꾸지 말라"는 단서에 주목하세요. 기계적 찾아 바꾸기와 AI 일괄 작업의 차이가 여기 있습니다. AI는 문맥을 보고 예외를 걸러 낼 수 있습니다.

**표기 교정.** 이 책의 규칙인 "도구 이름 첫 등장 시 한글(영문) 병기" 같은 표기 원칙도 전권에 한 번에 적용할 수 있습니다.

```
원고 전체에서 AI 도구 이름이 처음 나오는 자리를 찾아서
'한글 이름(영문 이름)' 형식으로 병기해줘.
두 번째 등장부터는 한글 이름만 남겨줘.
```

**호칭 변경.** 퇴고 중에 독자 호칭을 바꾸기로 했다면 이렇게 말하면 됩니다. "원고 전체에서 독자를 부르는 호칭을 '독자님'에서 '여러분'으로 바꿔줘. 문장이 어색해지는 곳은 자연스럽게 다듬어줘."

일괄 작업에는 제가 강조하는 **2단계 원칙**이 있습니다. 먼저 조사만 시키고, 확인한 뒤에 실행하는 것입니다. "아직 바꾸지 말고, 바뀔 곳의 목록만 먼저 보여줘"라고 요청해 목록을 훑어본 다음 "좋아, 실행해줘"라고 승인하세요. 그리고 큰 일괄 작업 전에는 반드시 앞 절의 저장을 먼저 해 두세요. 저장 → 조사 → 검토 → 실행. 이 리듬이 몸에 붙으면 전권 수정이 두렵지 않게 됩니다.

[저자 사례: 수강생이 탈고 직전 핵심 용어를 바꾸기로 결정했을 때, 예전 같으면 밤샘 작업이었을 전권 수정을 클로드 코드로 30분 만에 끝낸 이야기]

## CLAUDE.md로 내 책의 문체·규칙 가르치기

마지막 조각은 폴더 구조도에서 보셨던 `CLAUDE.md` 파일입니다. 이 파일은 특별합니다. **작업 폴더에 이 이름의 파일을 두면, 클로드 코드가 일을 시작할 때마다 자동으로 읽고 그 규칙을 따릅니다.** 새로 온 편집 조수의 책상에 올려 두는 업무 매뉴얼이라고 생각하시면 정확합니다.

이 파일이 없으면 어떻게 될까요? 매번 대화할 때마다 "내 책은 경어체고, 독자는 직장인이고, 과장된 표현은 쓰지 말고…"를 반복해서 설명해야 합니다. CLAUDE.md에 한 번 적어 두면, 그 설명이 모든 작업에 자동으로 깔립니다. 2부에서 배운 프로젝트 지침의 파일 버전인 셈인데, 원고 폴더와 함께 움직인다는 점이 다릅니다.

제가 쓰는 형태를 예시로 보여 드립니다. 그대로 베껴서 여러분의 책에 맞게 고쳐 쓰세요.

```markdown
# 이 책의 집필 규칙

## 책 소개
- 제목(가제): 퇴근 후 30분, 나의 첫 전자책
- 독자: AI를 잘 모르는 직장인과 예비 작가
- 저자 화자: 1인칭, 교육 경험이 있는 안내자의 목소리

## 문체
- 경어체를 쓴다: "~합니다 / ~해 보세요"
- 한 문단은 3~5문장. 짧은 문장 위주로.
- 독자는 "여러분"이라고 부른다.
- 번역투와 과장 표현을 쓰지 않는다.

## 표기 규칙
- 도구 이름 첫 등장 시: 한글(영문) 병기. 예: 클로바노트(CLOVA Note)
- 용어 통일: '전자책'(O) / 'e북', '이북'(X)
- 금액은 원화 기준, 달러는 $ 기호로 표기

## 금지 사항
- 수익을 보장하는 표현 금지 ("무조건", "누구나 월 천만 원" 류)
- 근거를 모르는 통계 수치 쓰지 않기

## 폴더 안내
- 원고는 원고/ 폴더의 챕터별 파일
- 목차의 기준은 기획/목차.md
- 원고를 수정하기 전에는 항상 바뀔 내용을 먼저 보여줄 것
```

이 파일 역시 손으로 다 쓸 필요가 없습니다. "지금까지 우리가 대화하며 정한 문체 규칙을 정리해서 CLAUDE.md 파일로 만들어줘"라고 시키면 됩니다. 그리고 집필 중에 새 규칙이 생길 때마다 이렇게 말하세요. **"방금 정한 규칙, CLAUDE.md에 추가해줘."** 이 한마디가 쌓이면, 여러분의 AI 조수는 책이 완성되어 갈수록 여러분의 책을 더 깊이 아는 조수가 됩니다. 이 파일은 12장에서 만들 자동화 레시피의 기초 체력이기도 합니다.

## 프롬프트 박스: 집필 시스템 구축 모음

```
[프로젝트 폴더 만들기]
기획/목차.md의 목차에 맞춰 원고 폴더에 챕터별 빈 마크다운 파일을 만들어줘.
파일명은 "번호-장제목" 형식, 각 파일 첫 줄은 "# n장. 제목"으로.
```

```
[하루 마감 저장]
오늘 작업을 버전으로 저장해줘. 바뀐 파일과 내용을 요약해 저장 메모에 남겨줘.
```

```
[되돌리기]
[파일명]을 [어제/특정 시점] 버전으로 되돌려줘.
되돌리기 전에 지금 상태도 따로 저장해 두고 진행해줘.
```

```
[전권 용어 통일 — 2단계]
원고 전체에서 '[바꿀 말]'을 '[통일할 말]'로 통일하려고 해.
아직 바꾸지 말고, 바뀔 위치 목록을 파일별로 먼저 보여줘.
(검토 후) 좋아, 인용문 안은 제외하고 실행해줘. 결과를 표로 보고해줘.
```
