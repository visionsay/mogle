# 12장. 집필 자동화 레시피

11장까지 마친 여러분의 원고 폴더는 이미 훌륭한 집필 시스템입니다. 그런데 며칠 써 보면 새로운 사실을 발견하게 됩니다. 좋은 지시일수록 길다는 것. 교정을 시킬 때마다 "경어체 확인하고, 번역투 잡고, 표기 병기 확인하고, 문단 길이 보고…"를 다시 입력하는 것도 일입니다. 잘 만든 지시문을 어딘가에 복사해 두고 매번 붙여넣고 계시다면, 이 장이 바로 그 수고를 없애 줍니다.

요리에 비유하면 이렇습니다. 지금까지는 매번 레시피를 처음부터 불러 주며 요리를 시켰습니다. 이제는 레시피 카드를 주방에 걸어 두고 "그 요리, 시작해"라고만 말하는 단계로 갑니다. 이 장이 약속하는 것은 **한 번 만들어 두면 한마디로 실행되는 나만의 집필 자동화 레시피북**입니다. 클로드 코드의 두 기능, 스킬(Skills)과 루틴(Routines)이 그 도구입니다.

## Skills로 나만의 교정 체크리스트 패키징하기

스킬은 한마디로 **이름 붙인 작업 절차**입니다. 자주 쓰는 지시문과 체크리스트를 하나의 스킬로 묶어 폴더에 저장해 두면, 다음부터는 "교정 스킬 실행해줘" 한마디로 전체 절차가 돌아갑니다. 11장의 CLAUDE.md와의 차이를 짚어 두겠습니다. **CLAUDE.md는 모든 작업에 늘 적용되는 기본 규칙**이고, **스킬은 부를 때만 실행되는 작업 절차**입니다. 사훈과 업무 매뉴얼의 관계라고 생각하시면 됩니다.

스킬의 실체는 폴더 안에 저장된 안내문 파일입니다. 어떤 이름의 스킬인지, 언제 쓰는지, 어떤 순서로 무엇을 하는지를 적어 둔 문서일 뿐입니다. 형식을 외울 필요는 없습니다. 만드는 일 자체를 클로드 코드에게 맡기면 되니까요.

```
내 교정 체크리스트를 '원고 교정'이라는 스킬로 만들어줘. 체크리스트는:
1. 경어체("~합니다/~해 보세요")가 아닌 문장 찾기
2. 번역투 표현 찾기 ("~에 대하여", "~적인", "그것은" 남용)
3. 한 문단이 6문장을 넘는 곳 찾기
4. 도구 이름 첫 등장 시 한글(영문) 병기 확인
5. 금지 표현("무조건", "100% 보장") 찾기
결과는 파일별 표로 정리하되, 원고를 바로 고치지 말고 보고서만 만들어줘.
```

이렇게 요청하면 클로드 코드가 스킬 파일을 만들어 줍니다. 대략 다음과 같은 모양입니다. 내용을 이해할 수 있도록 예시를 보여 드리지만, 직접 타이핑할 일은 거의 없습니다.

```markdown
---
name: 원고-교정
description: 원고 폴더 전체에 교정 체크리스트를 적용하고 보고서를 만든다.
---

# 원고 교정 절차

1. 원고/ 폴더의 모든 .md 파일을 읽는다.
2. 아래 체크리스트로 점검한다.
   - 경어체가 아닌 문장
   - 번역투 표현: "~에 대하여", "~적인" 남용, "그것은" 남용
   - 6문장을 넘는 문단
   - 도구 이름 첫 등장 시 한글(영문) 병기 누락
   - 금지 표현: "무조건", "100% 보장" 류의 수익 보장 문구
3. 원고 파일은 수정하지 않는다.
4. 결과를 산출물/교정-리포트-[날짜].md 파일에 표로 저장한다.
   표 구성: 파일명 / 위치 / 문제 유형 / 원문 / 수정 제안
```

이제부터 퇴고 세션은 "원고 교정 스킬 돌려줘"로 시작됩니다. 보고서를 훑어보고 "3번과 7번 제안만 반영해줘"라고 고르면 됩니다. 스킬은 여러 개 만들 수 있습니다. 저는 수강생들에게 '원고 교정' 외에 '팩트체크 표시'(출처 없는 수치에 확인 표시 달기), '분량 점검' 스킬을 기본 3종으로 권합니다. 6장에서 다듬은 여러분의 교정 프롬프트들이 그대로 스킬의 재료가 됩니다.

스킬의 진짜 가치는 **품질의 일관성**입니다. 사람은 피곤한 날 체크리스트를 건너뜁니다. 스킬은 열두 번째 챕터에도 첫 챕터와 똑같은 기준을 적용합니다. 그리고 체크리스트가 발전하면 "교정 스킬에 '중복 표현 찾기' 항목을 추가해줘"라고 말하면 됩니다. 레시피 카드는 계속 자랍니다.

어떤 작업을 스킬로 만들지 감을 잡는 기준은 간단합니다. **같은 지시를 세 번째 입력하고 있다면, 그것이 스킬 후보입니다.** 수강생들이 실제로 만들어 쓰는 스킬 몇 가지를 소개하면 이렇습니다. 챕터 초고를 끝낼 때마다 도입부가 약속한 내용을 본문이 지켰는지 확인하는 '도입-본문 일치 점검', 인용문마다 출처 메모가 붙어 있는지 확인하는 '출처 점검', 각 장 끝의 실습 과제가 실제로 30분 안에 가능한 분량인지 따져 보는 '실습 난이도 점검'. 여러분 책의 반복 작업이 곧 여러분만의 스킬 목록이 됩니다.

## Routines로 매주 전체 원고 교정 패스 예약하기

스킬이 레시피라면, 루틴은 **예약 실행**입니다. Claude의 루틴 기능을 쓰면 정해 둔 작업을 정해진 시간에 자동으로 실행할 수 있습니다. "매주 금요일 아침, 전체 원고에 교정 패스를 돌려라"처럼요. 3장에서 ChatGPT의 태스크(Tasks) 기능으로 아침 집필 알림을 받아 보셨다면, 루틴은 거기서 한발 더 나아갑니다. 알림을 보내는 데 그치지 않고, **파일을 읽고 보고서를 만들어 두는 실제 작업**을 예약할 수 있다는 점이 다릅니다.

제가 추천하는 기본 루틴은 **주간 교정 패스**입니다. 이렇게 요청해 보세요.

```
매주 금요일 오전 8시에 실행되는 루틴을 만들어줘.
할 일: 원고 폴더 전체에 '원고 교정' 스킬을 실행하고,
결과 보고서를 산출물/주간교정/ 폴더에 날짜를 붙여 저장해줘.
지난주 보고서와 비교해서 새로 생긴 문제와 해결된 문제를 요약해줘.
```

금요일 아침 커피를 내리는 동안 한 주치 교정 보고서가 준비되어 있는 경험은, 혼자 쓰는 사람에게 편집부가 생긴 것 같은 감각을 줍니다. 여기에 11장에서 익힌 저장 습관을 얹어 "매일 밤 원고 폴더의 변경 사항을 버전으로 저장하는 루틴"을 더하면, 저장을 깜빡한 날도 안전망이 작동합니다.

자동화에는 원칙이 하나 필요합니다. **자동 실행된 결과물도 반드시 사람이 검수한다.** 그래서 저는 루틴에게 원고를 직접 고치게 하지 않고, 보고서를 만들게 합니다. 고치는 결정은 금요일 아침의 여러분이 내리는 것입니다. 만에 하나 자동 작업이 잘못되어도 11장의 버전 관리가 있으니 되돌리면 됩니다. 자동화는 판단을 대신하는 것이 아니라, 판단할 재료를 미리 차려 놓는 것입니다.

[저자 사례: 주간 교정 루틴을 켜 두고 마감 3주를 보낸 경험 — 금요일 보고서 덕분에 탈고 직전 몰아치기 교정이 사라진 이야기]

## 원고 → 보도자료·상세페이지·SNS 콘텐츠 일괄 생성 (OSMU)

이제 시선을 출간 이후로 돌려 봅시다. 5부에서 자세히 다루겠지만, 책이 나오면 홍보 콘텐츠가 대량으로 필요합니다. 보도자료, 판매 플랫폼용 상세페이지, SNS 게시물까지. 이것을 원고에서 한 번에 뽑아내는 것이 OSMU(One Source Multi Use), 원소스멀티유즈입니다. 제가 쓰는 기본 공식은 이렇습니다. **원고 1챕터 → 카드뉴스 1세트 + 쓰레드 글 5~7개 + 릴스 대본 1편 + 뉴스레터 요약 1편.**

채팅형 AI로도 한 챕터씩은 가능했습니다. 클로드 코드가 다른 점은 **전체 원고를 읽고, 여러 산출물을 파일로 한 번에 만들어 저장**한다는 것입니다. 이렇게 요청해 보세요.

```
원고 전체를 읽고 산출물 폴더에 홍보 콘텐츠 초안을 만들어줘.
1. 보도자료.md — 책 소개, 저자 소개, 목차 하이라이트, 추천 독자 (A4 1장 분량)
2. 상세페이지.md — 판매 플랫폼용. 독자의 고민 → 이 책의 해결책 → 목차 → 미리보기 발췌 순서로
3. SNS/ 폴더 — 각 장에서 핵심 팁을 뽑아 쓰레드용 짧은 글 5개씩
4. 뉴스레터-창간호.md — 책의 핵심 메시지를 담은 발행용 원고
전부 초안이라고 파일 맨 위에 표시하고, 원고의 문체 규칙(CLAUDE.md)을 따라줘.
```

몇 분 뒤 산출물 폴더에는 홍보 콘텐츠 초안 수십 개가 정리되어 있을 것입니다. 한 가지 요령을 더하면 품질이 올라갑니다. 매체마다 어울리는 말투가 다르다는 점을 지시에 담는 것입니다. 보도자료는 격식 있는 문어체로, 쓰레드는 짧고 구어체로, 상세페이지는 독자의 고민에 말을 거는 톤으로. "매체별 톤 가이드"를 CLAUDE.md에 한 번 적어 두면, 이후의 모든 OSMU 작업에 자동으로 적용됩니다. 11장에서 만든 규칙 파일이 홍보 단계에서도 일하는 셈입니다.

여기서도 원칙은 같습니다. **AI 초안 + 사람 검수.** 특히 SNS에 나가는 글은 여러분의 목소리로 다듬는 마지막 손질이 팔로워와의 신뢰를 만듭니다. 다듬은 콘텐츠를 카드뉴스로 만들고 예약 발행하는 도구들은 13장에서 이어집니다. 4부의 클로드 코드가 콘텐츠 공장이라면, 5부의 도구들은 유통망인 셈입니다.

## 실전 레시피 모음: 목차 대조 검사, 분량 리포트, 마감 대시보드

마지막으로, 제가 실제 집필에서 매주 쓰는 레시피 세 가지를 그대로 드립니다. 셋 다 스킬로 저장해 두면 한마디로 실행됩니다.

**레시피 1: 목차 대조 검사.** 집필이 진행되면 원고는 목차에서 조금씩 이탈합니다. 장 제목을 바꿔 놓고 목차 파일은 안 고치거나, 계획한 절을 빼먹기도 합니다.

```
기획/목차.md와 원고 폴더의 실제 파일들을 대조해줘.
1. 목차에는 있는데 원고 파일이 없는 장
2. 원고 제목과 목차 제목이 다른 장
3. 목차의 절 중에서 본문에 해당 내용이 없는 것
세 가지를 표로 정리해줘. 파일은 고치지 마.
```

**레시피 2: 분량 리포트.** 출간 기획서에서 정한 분량 목표(예: 장당 6,000~9,000자)를 지키고 있는지 숫자로 확인합니다.

```
원고 폴더의 챕터별 글자 수(공백 포함)를 세서 표로 만들어줘.
목표는 장당 6,000~9,000자야. 목표 미달/초과인 장을 표시하고,
전체 원고 분량과 목표 대비 진척률(%)도 계산해줘.
```

**레시피 3: 마감 대시보드.** 위의 두 레시피에 최근 작업 기록까지 합쳐, 내 책의 현황판을 파일 하나로 만드는 레시피입니다.

```
산출물/대시보드.md 파일을 만들어(있으면 갱신해) 줘. 내용은:
1. 챕터별 상태 표: 분량 / 목표 대비 % / 마지막으로 고친 날짜
2. 목차 대조 검사 결과 요약
3. 최근 일주일의 작업 기록 요약 (버전 저장 기록 기준)
4. 남은 마감일([마감일]) 기준으로 이번 주에 써야 할 분량 제안
```

이 대시보드 갱신을 앞 절의 루틴에 걸어 "매주 월요일 아침"으로 예약해 보세요. 월요일마다 내 책의 진척률과 이번 주 할 일이 적힌 현황판이 갱신되어 기다리고 있습니다. 30일 로드맵의 후반부를 완주하게 만드는 것은 의지가 아니라 이런 장치입니다. 이 장의 레시피들과 부록 D의 치트시트를 함께 두고 쓰시면, 클로드 코드는 조수에서 집필 스튜디오의 상주 스태프가 됩니다.

## 프롬프트 박스: 자동화 레시피 핵심 모음

```
[스킬 만들기]
내가 알려주는 체크리스트를 '[스킬 이름]' 스킬로 만들어줘.
체크리스트: [항목들]. 원고는 고치지 말고 보고서만 산출물 폴더에 저장하도록.
```

```
[스킬 실행과 반영]
'[스킬 이름]' 스킬을 원고 전체에 실행해줘.
(보고서 확인 후) 보고서의 [번호] 제안만 원고에 반영해줘.
```

```
[주간 루틴 예약]
매주 [요일] [시간]에 '[스킬 이름]' 스킬을 실행하고
결과를 산출물 폴더에 날짜별로 저장하는 루틴을 만들어줘.
지난 보고서와의 변화도 요약해줘.
```

```
[OSMU 일괄 생성]
[챕터 파일명]을 읽고 산출물 폴더에 만들어줘:
쓰레드용 글 5개, 카드뉴스 문안 1세트(8장), 릴스 대본 1편, 뉴스레터 요약 1편.
문체는 CLAUDE.md 규칙을 따르고, 파일마다 '초안' 표시를 넣어줘.
```

- [ ] 스킬을 실행해 첫 교정 보고서를 받고, 제안 중 3개를 골라 반영시킨다.
- [ ] 매주 금요일 아침의 주간 교정 패스 루틴을 예약한다.
- [ ] 분량 리포트 레시피를 실행해 현재 진척률을 확인한다.
